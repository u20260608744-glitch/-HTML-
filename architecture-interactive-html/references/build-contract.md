# 数据与实现契约

## 1. 项目数据与组件分开

项目数据负责事实、来源、对象映射、图纸与指标；组件负责布局、状态、交互；主题只负责视觉。不要把项目名称、方案数量、功能种类、图纸比例和统计值写进通用组件。

建议目录：`inputs/` 原始文件清单（不必复制整个源库）、`data/` manifest与语义映射、`assets/` 本地素材、`src/` 组件与主题、`dist/` 成品、`qa/` 验证记录。已有项目组织合理时复用它。

入口数据见 `assets/project-intake.json` 和 `assets/project-manifest.schema.json`。schema管结构；单位、证据与能力仍需实际检查。一个数值对象至少包含：

```json
{"value":null,"unit":"m2","status":"unknown","source":null,"basis":null}
```

建议 status：`source`原文、`measured`有方法的实测/几何测量、`derived`有公式的推导、`assumed`明确假设、`unknown`未知、`not_applicable`不适用。source引用资产ID、页码/对象ID/表格行与版本。confidence如使用，应有依据；高confidence不将假设变成事实。

`project.constraints` 可记录数值型 metric，也可记录文字型限制：`id/label/statement/status/source`，例如保留现状乔木、禁止修改源几何。区间指标使用 `range:[下界,上界]` 与 `value:null`；单值与区间互斥，不自动取中值。结构校验以外还需检查上下界顺序、ID唯一性、引用存在与证据可读性。

独立保存 `capabilities`：模型浏览、语义着色、剖切、地图、校准比例尺、指标、原册。记录 ready/degraded/blocked/not_requested 与实际依据。构建时根据能力显示操作，不以一个总布尔值控制全部能力。

执行 schema 校验后还需检查引用关系：ID 唯一、资产/方案/分类引用存在，`defaultLocale` 属于 `locales`。成品启用主题切换时，`themeId` 必须属于非空的 `enabledThemeIds`，默认主题与其他主题都要真实实现；输入表中的空数组只用于发现阶段。

## 2. 状态、对象与跨章节联动

稳定状态包含 `activeSchemeId`、语言、主题、相机预设、rotation、显示材质、功能选择、原册页/阅读模式。不同组件有独立临时状态：用户拖动相机、图纸zoom、阅读详情展开等。

接口可采用以下语义，不要求具体框架：

```text
selectScheme(id)         同步总图/剖面/功能/指标及入口上下文
selectLanguage(locale)   更新正文/按钮/图注/热点，不重置用户相机
selectView(preset)       明确改变相机；首个axon恢复自动旋转（减少动态除外）
setRotation(enabled)    手动暂停保留当前相机
openModel(id)            唯一主入口或明确方案上下文入口
openBook(pageId)         进入对应原页，不使用未核页码
setTheme(themeId)        仅改变视觉，不换几何、数值与源页
```

语言/主题变化不能重新初始化全部WebGL、破坏已选方案或将手动调整的相机归零。仅显式视图/方案操作按约定fit；resize可对未手动操作的初始视图重新fit，用户相机保持其关系和可见状态。

将周边挂在独立组，`setContextVisible/style` 不修改主体相机。真实源树/车与替代配景分开保存，处理Z冲突优先presentation offset/material，不改源position buffer。

## 3. 从源模型得到浏览器几何

检查可调用解析器/导出工具再选择路线。使用已有源导出或GLTF/GLB；保留原点、轴向、单位、层级和变换链。转换后核对若干已知对象、顶点/三角数量、尺寸与方案映射，保存转换方法及允许的精度误差。

语义需来自图层、原对象名称、来源文档或用户确认。白色材质并非一定建筑，绿色并非一定景观，某Z值不是楼层语义。合并材质mesh时，一个buffer可能混合建筑/汽车/地面；用provenance的face/index ranges识别主体，不能用整个material bucket包围盒。

源剖面基于明确切线/面和保留侧，从几何真实相交得到切线/闭合轮廓；原剖面图片仅做阅读。轮廓闭合证据不足时不填实体。地下室、核心筒、屋顶和植物不能因为文本提到而假装源模型已存在。

渲染、功能着色、outline、阴影与展示位移是独立可复用表示；原positions/normals/indices及物体world transform应保留原始证据。不为居中修改各建筑坐标。

## 4. 建筑主体对齐图幅中心：可验证算法

1. 从native building roots/明确语义选取建筑主体：住宅、配套、建筑平台等属于建筑的子对象；排除周边、平场地、树、汽车。若平台是独立场地而非建筑，按实际语义处理，不按视觉任意取舍。
2. 遍历实际被索引的源顶点，应用完整world transform，以实际渲染数值精度计算（如Float32）；不把unused vertices或不可见项目误纳入。
3. 保留可信原生相机方向/up/FOV。没有原生相机时用项目适合的轴测方向；标为新观看相机。
4. 对候选distance计算真正透视投影：`clip = projection × view × world × vertex`，除以w；由NDC得到bitmap坐标 `x=(ndc.x+1)W/2, y=(1-ndc.y)H/2`。
5. 得主体bbox `minX/maxX/minY/maxY`，中心 `c=((minX+maxX)/2,(minY+maxY)/2)`。让projection window/film shift修正 `c - (W/2,H/2)`。修改取景窗口，而非移动源建筑。
6. 在多个方案比较时，以所有方案的投影范围和目标图框最窄比例计算一组共同的镜头distance/scale，保留比较意义；单方案按其范围fit。别用周边extent反推主体比例。
7. 缩略图采用center-cover后重新验证实际图框：`s=max(frameW/bitmapW,frameH/bitmapH)`；偏移 `ox=(frameW-s*bitmapW)/2, oy=(frameH-s*bitmapH)/2`；显示bbox `ox+s*bboxX, oy+s*bboxY`。两轴主体中心误差目标≤1 CSS px，边缘预留合理安全边距，裁切范围避开建筑。
8. 极端画幅不能在同一固定bitmap里兼顾完整建筑与cover时，重新按该aspect渲染或采用不同aspect的source-backed缩略图；不非等比拉伸，也不降低“完整建筑”的含义。

透视的三维中心投影未必等于图像bbox视觉中心，因此只 `lookAt(worldBox.center)` 不足以证明构图居中。记录每方案选取的source范围、camera、bitmap尺寸、投影bbox与crop后误差。

## 5. 总图配准、北向与尺度

模型投影、场地底图、功能填色和标尺须共享一套配准/视域。记录源轴向、坐标变换、控制点或已知长度。未知单位/北向时可阅读图纸，禁止新生成真实比例尺/真北承诺。

若正交图宽 Wpx 对应 Lm，比例尺长度 tm 为 `Wpx*tm/Lm`；也可投影两个相距tm的world points测pixel差。展示容器等比缩放后标尺同比缩放；不能把比例尺直接压窄却保留“50m”。允许选择更短的tm，然后重算ticks与长度。

图幅边缘可裁掉周边，但总图自身完整、北针和标尺在最终frame内。北针放右侧并区分 geographic north、模型+Y、原册示意北；对未知项不伪装精确。总图保持已校准比例，图片不能各轴单独stretch。

## 6. 指标与分析内容

法定 FAR = 计容建筑面积 / 规定的用地面积；只有口径明确才作法规数值。若只有地上面积，可提供明确注明“地上面积/用地面积”的比较推导，不冒称法定计容。密度分母和建筑基底口径也要明确。

任务面积余量 = 已确认上限 - 同口径面积；剩余可为负，不截成0。车库概算 = 可用于停车的明确面积 / 用户或可靠依据确认的单车位综合面积，表达为区间/概算，不伪造实际布局容量。

场地尺度应总结有证据的类型、层数/高度、空间分布、研究范围和覆盖口径。着色片区面积不是建筑基底面积；从层数换算高度属于假设，要给层高假设/范围。没有实测依据时不制作精确小数面积。图示研究半径不是实际可达步行路程。

评分只在用户希望排序且权重/依据明确时启用。主观评分与原面积事实分开，默认直接比较原值，不伪造“最优方案”。

## 7. 图文排版与一屏章节

桌面优先 `minmax(0,1fr)` 网格与共享行轨道；3卡比较可用subgrid，其他N按宽度切grid/selector。图框相同宽高、主图同顶同底、相应说明行起点一致、每段在自己的逻辑行槽内。不同字数导致文字墨迹底部不同是正常的，不强行增加字数；比较的是轨道边界和整组首尾。

场地页先确定几类分析共用的frame高度与右侧map高度，再将site图纳入同一规则。左图等比cover时，检查源图内legend/header/source文字是否完整；关键内容不裁，无法裁时使用可核的源图重排或contain+有意义留白，不能AI补造地图地貌。

一屏高度根据当前viewport扣除需要的header、章标题、操作、注释，不用大量固定px造成头尾截断。约束正文最小可读字号（通常中文13px、英文12px作为工程起点，按密度/读者调整）。内容超出预算时拆成有意义的相邻小章或细节阅读区；关键结论与配图、指标仍同显，不能用隐藏/切换造成阅读任务割裂。

手机优先单列、可触摸入口和自然竖向阅读；复合愿景/回应、模型/说明、总图/指标保持同一页阅读，不为了“每章一屏”截断内容。安全处理横屏、浏览器工具栏高度变化、100svh/dvh与缩放。避免全屏scroll snap锁定导航。

图纸主展示若需要无边条就给frame与原图同aspect或选正确contain策略，不靠伪背景伸展篡改原内容。书页的装饰纸叠层不得留下无解释的白色横条。

## 8. 原册、离线依赖与运行能力

原PDF/PPTX转换为有序原页图，保存每页来源、尺寸与页码。原页P不固定，宽高比可不同；整页阅读不裁图字。支持的single/spread布局以各页aspect计算，不硬编码1448px或4:3。没有完整原册时以已提供的图纸计数，标题说明范围。

读页入口与顶层“打开原册”避免在同一区域重复；指标的“打开方案总图第x页”是不同上下文，可保留。双页阅读、zoom、目录、拖角翻页、左右键、Home/End、Esc与触摸均须具有真实对应行为；复杂3D翻页效果可按设备能力简化，不损失内容访问。

单HTML离线：CSS/JS/runtime/images/fonts/model全嵌入且有许可；关闭网络实测。GLTF外部纹理、Draco/KTX解码器、workers、WASM和module import也算依赖，要本地嵌入或改用自包含版本并实际验证file://行为。不能因为script有data URI就声称没有外部请求。

性能预算随模型/设备决定。优先压缩有序图页、懒初始化组件、仅对viewport内活动模型渲染、限制同时开启WebGL canvas、暂停不可见动画。若做LOD/decimation，只在明确允许的浏览器展示副本上执行，保存原文件/误差与参数；不替换原模型。

无WebGL时展示真正源模型缩略图/原册并说明降级，禁用无效旋转/剖切控件。没有执行环境的GPT可以交付完整代码与运行说明，测试状态必须是未运行。
