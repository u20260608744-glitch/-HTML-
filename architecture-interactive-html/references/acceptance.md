# 验收、回归与交付

只检查当前任务实际启用的能力，并据风险选择测试。禁止把原案例的旧报告直接当新项目/新主题已通过；本规范不是增加无用测试数量的理由。

视频验收仅在用户请求视频时启用，见 [视频制作流程](video-production.md) 与本文件第8节。HTML和影片分别记录来源版本、实际能力与验证状态；没有视频工具不影响已完成的HTML验收。

## 1. 输入与能力

- 文件读取成功与类型匹配；转换前后原文件hash一致。
- scheme数量、名字、稳定ID、模型组、图纸和指标映射正确。
- 未知数值保留null/未知；数字格式化前显式检查null/undefined/finite，避免`Number(null) → 0`。
- 已提取条件及缺项经过说明；被阻塞的能力无虚假有效按钮。
- project/metric/programme/source的事实、推导、假设和口径分开；每个核心指标有来源定位。

## 2. 构图与排版

实际加载最终成品而非临时注入版，测量真实DOM与源投影数据。

| 检查 | 可验证标准 |
|---|---|
| 建筑居中 | 根据源建筑indexed vertices独立投影；crop后bbox中心与frame中心两轴目标≤1 CSS px |
| 主体完整 | frame内四侧有合理留边，通常至少10px作为初始检查；所有建筑平台/边缘完整，极端画幅重新render |
| 图框齐平 | 同比较组top/bottom/height一致，允许亚像素舍入误差约1px；宽度按网格一致 |
| 文字齐平 | 共用逻辑行槽的起点和slot边界、组首尾齐平；每条正文完整在自己的槽里，无实际重叠；自然墨迹行尾不要求一致 |
| 图片等比 | 单一scale，fill策略与内容一致；无非等比transform，无不可解释空条 |
| 场地稳定 | 切换全部分析种类，map高度、主图frame、侧栏边界一致，无突变或裁字 |
| 总图 | 主图与指标组上下齐平；北针在右侧、依据明确；标尺与已校准视域一致 |
| 一屏桌面 | 默认章frame适合目标viewport，关键图/结论/指标同显，实际文字Range不超frame |
| 手机 | 正文和操作完整，无页面横向溢出，无遮挡；复合内容自然滚动；不能靠隐藏关键文字达成一屏 |

图表轴标题、legend、页脚/页码/来源等需要阅读的元素也检查。不要只根据img元素的rect判断实际contain/cover绘制内容完整。

## 3. 真正交互

用正常鼠标/触摸/键盘操作，不靠强制点击、改状态或mock返回值证明功能。

- **模型**：每个实际方案打开正确源geometry，旋转/平移/缩放有效；回首个axon行为符合约定；手动冻结不复位；context切换不改主体相机；无WebGL真降级可用。
- **功能**：每个热点指向相应源分类/可见表面，说明对应同方案；操作显示样式不改变源buffers；语义缺失时不假着色。
- **剖面**：切线/范围正确，无源闭合证据时不填实体；展示阴影与真日照表述一致，配景不钻建筑。
- **原册**：页数从输入读出，首尾、前后、目录、single/spread、zoom/pan、Esc/左右键/触摸有效；页比和内容完整，装饰层无白横条；焦点回到发起入口。
- **同步**：方案/语言/主题切换及DOM重建后，模型、总图、指标、热点和按钮仍对应同ID；保留相机/页码/阅读状态；长英文重新测量。
- **动效**：正常和减少动态模式分别测；不可见canvas不持续渲染，自动旋转可暂停，减少动态默认不自动启动。
- **去重**：同一区域同功能只一个主入口；所有导航、方案/页码上下文入口仍有真实目的，点击后的目标不同则不能误删。

## 4. 建议矩阵

初始可选：桌面1920×1080、1280×720、手机390×844；按用户目标设备增加1440×900/横屏/平板，不因范例尺寸固定不适配。

覆盖所有启用语言、方案与风格的关键状态；数据源/组件未改时可只回归受影响模块。多风格成品每种主题至少大屏/小屏截图，风险集中主题做完整矩阵。不要求穷举无意义的状态排列。

性能记录用实际对象/triangle数量、纹理大小、HTML体积、主要加载时间和明显操作卡顿；目标设备能力不同，阈值以用户要求/实测确定，不承诺任何模型在所有设备流畅。

## 5. 离线与准确交付

对最终`file://` HTML关闭网络运行，确认runtime、字体、图纸、解码器等自身加载不发外部请求。点击外部出处属于用户选择，不等同运行时网络依赖。多文件交付检查相对路径和启动方法，不只在开发server测成功。

可记录 `build-receipt.json`：最终hash、源文件hash、实际能力、原册页数、方案IDs、派生图相机/比例、主题IDs、来源与依赖。QA记录最终hash、测试环境、实际操作、截图、失败项和未测试项。没有执行工具标记not_run，禁称通过。

更新既有交付时：保存版本备份，核对已测候选与最终文件hash一致，按正常入口打开。原工作文件保留，不为了出HTML覆盖模型或源册。不要自动上传、公开部署或调用付费服务。

## 6. 现实缺资料的合格交付

用户仅有8页PDF和两张效果图，要求双语与3种风格，未提供模型/面积/单位/语义。可交付：8页真实原页阅读、目录缩放、来源图文、中英文与3主题；其余能力逐项降级。没有几何就没有真orbit/切剖/模型量测；没有面积/口径就无FAR/密度/停车数字；缺北向就无伪真北。页面仍可以完成，报告不能称“完整模型交互完成”。

若用户有单方案GLB及面积表但无功能映射：可提供真orbit与同方案指标；单方案不凑比较，功能语义待核，预览图片不能当功能高亮。

## 7. 最终提交给用户的内容

1. 可打开的HTML或明确的本地文件夹及启动入口。
2. 简短使用方式、主要实现能力与选定风格。
3. 来源/指标口径、真正缺项、未验证能力及其补充资料。
4. 需要维护时提供source/data与build/QA记录；没有必要不把实现细节堆进产品页。
5. 已请求且实际制作的视频，另附对应MP4、字幕、封面/打包文件及视频来源/许可/QA摘要。没有实际媒体执行工具时交付讲稿分镜和未执行说明，不能称已导出成片。

详细来源/假设可放折叠资料区，关键未知状态直接就近显示。正文不要铺满“纯技术实现说明”，但必须让读者能区分概算与真实指标。

## 8. 可选视频验收

对母版及每个横竖派生版本检查，不能将母版通过自动复制为所有版本通过。保存最终文件hash、录制HTML快照hash、时间轴/字幕hash、工具版本、成功/失败/未测项。当前HTML与录制快照不同则明确列出，不能借当前网页QA证明旧影片反映了新版。

| 项目 | 可验证标准 |
|---|---|
| 硬时限 | 用户要求5分钟内时，最终每份MP4 `format.duration ≤300.000秒`；剪辑以295秒为推荐预算。核对音视频流起止，不能只用旁白时长或视频帧数判断 |
| 时间轴 | 整数帧起止连续、镜头总帧数与段/全片一致；必要动作与旁白有可用时间；没有无意的黑帧、重复片段或丢失片尾 |
| 来源与缓存 | source/动作/裁剪/讲稿/字幕/参数/适配器版本组成缓存依据，导出和验收期间文件hash不变；原HTML/模型/原册未被制作视频流程覆盖 |
| 真实互动 | 所选源区间在clip及实际动作范围内，原速播放；方案/功能/页码正确。旋转有原生相机/旋转状态与画面变化证据，不能只靠像素差或“video”标签证明 |
| 来源口径 | 讲稿数字/地名/方案与原资料一致；概算、主观比较、观看阴影及概念补模未被剪辑为法定指标或性能结论 |
| 覆盖与阅读 | 必须条目覆盖；快速浏览与详细讲解分开；原册页序正确、不虚构页数/案例；图纸小字需要阅读时有足够时间或特写 |
| 编码与画幅 | 实测分辨率、fps、编码、像素格式、SAR/DAR、声道/采样率与目标一致；当前schema兼容预设为MP4/H.264/yuv420p/SAR1/AAC，其他编码需扩展契约与实现；画幅不能非等比拉伸 |
| 字幕与章节 | 依据实际配音定位，全局偏移包括段首留白；字幕不超过片尾、不遮主图，章节标记与内容起点对应；外置UTF-8 SRT与对应版本一致 |
| 音频 | 记录许可/出处、实际时长、响度/真峰值/削波；人声和空隙样本核对配乐电平，片尾重新渐出；试听范围如实记录，不把响度测量冒充完整听审 |
| 完整解码 | 对最终文件全部视频和音频流解码并检查错误；开头播放或几张截图不能代替全流检查。缺编码器/探测/解码工具标记not_run |
| 发布下载版 | 手机/桌面抽帧核对字幕、主体、图例与读数；横竖各自验收时长/比例/音频；封面无重要内容裁切，ZIP能解压并核验内部CRC/hash |
| 发布状态 | 只有本地导出/验证时写“适配下载文件”；未实际上传不称平台接受。视频号、朋友圈、聊天文件的限制分开，当前未确认的限制保持未知 |

AAC编码可能补齐末帧，验收报告应记录容器呈现时长与独立解码PCM样本差异。少量补齐须用具体样本数解释；超过合理编码补齐的差异继续查同步/截断问题，不能忽略大漂移，也不能因此放宽300秒硬上限。

每章及关键旋转/切换至少有对应抽帧或短段检查，字幕/画面/旁白共同核对。更新部分镜头后失效相关缓存并刷新最终报告；源区间变化需要重查真实动作，不能沿用旧分镜检查结果。技术全解码、抽查画面与实际试听分别说明范围，不称未进行的连续观看/听审。
