# 可选建筑汇报视频：输入、制作与验收

视频只在用户请求时制作。HTML、原模型、图纸与原册继续作为独立成果保留；制作视频不授权改建筑几何、覆盖已交付文件或发布到社交平台。视频的方案数、章节数、功能类别与册页数来自当前项目，不继承参照案例的三方案、11章、75镜头或17页。

本文件与 [输入条件](input-requirements.md)、[用户填写表](user-intake.md)、[HTML验收](acceptance.md) 配合使用。[视频输入模板](../assets/video-intake.json) 与 [视频manifest schema](../assets/video-manifest.schema.json) 单独描述视频请求；普通用户可只用文字说明，由agent整理配置。不要将视频字段随意塞入不接受这些字段的HTML manifest。

模板中的 `requested=false` 表示默认不制作视频；英文女声、器乐、双比例、295秒及25fps为可覆盖预设。会话或HTML已经明确语言、声音、比例时沿用，不能被模板覆盖；没有既定偏好时可采用模板预设并说明选择。无旁白设 `voice.enabled=false`、音轨为空，按可读画面时间排镜；实现若需要静音占位须实际生成并标明无声，不能把未生成的旁白标成已完成。

真实图文片可以没有HTML：`source_html` 与 `source_html_sha256` 均为空，改用非空 `source_assets` 保存真实素材的路径、hash与类型。准备录制HTML时必须同时提供对应源文件与hash；规划阶段不因没有可运行HTML就虚构它存在。

## 1. 先确定真实输入与可交付级别

| 输入类别 | 必须明确的内容 | 由agent提取的内容 | 可选偏好与降级 |
|---|---|---|---|
| 内容与目标 | 至少一份可读取资料；讲给谁听、必须说明什么；已有任务文字可作为依据 | 项目事实、来源定位、方案ID、章节、功能分类、页序及冲突 | 没有模型可做图文讲解；不能称已录制模型旋转 |
| 源版本 | 要使用的HTML/素材版本；多份候选存在冲突时只确认版本映射 | 实际路径、SHA256、依赖、可用语言/主题与控制接口 | 没有可运行HTML时可据真实图纸制作视频；不能称真实HTML互动片 |
| 时长与覆盖 | 用户已指定的硬上限、核心条目、是否需要逐页详解 | 从资料列出可讲内容，估算阅读与操作时间 | “约5分钟”和“不得超过5分钟”分开处理；不固定字数或镜头数 |
| 声音与字幕 | 用户明确的语言、声音或无旁白要求；使用音轨的来源与许可 | 已有音轨的时长、采样率、声道、字幕或词边界 | 沿用会话/HTML已明确偏好，否则采用说明后的可覆写预设；音色、语气、字幕语言可调整 |
| 音乐 | 若使用第三方音乐，许可须覆盖本次使用场景 | 来源、授权记录、署名、音轨hash；原创合成的脚本/种子 | 配乐风格、是否配乐可选；没有许可不下载未知音乐凑完整片 |
| 展示与输出 | 用户已指定的横竖比例、接收方式、必须保留的内容 | 目标画幅、字幕区域、现有设备/编码工具、空间预算 | 品牌、封面、片头、配乐、多个风格样片、体积上限均按需求选择 |

先读取已有信息，再输出“已具备 / 真正缺项 / 可先做”。不要重复要求用户填写可自动提取的DOM选择器、相机坐标、音频时长或视频编码字段。单位、真北、功能语义、指标口径沿用HTML的来源规则；剪辑不能把概算变为法定指标，把观看阴影变为日照性能。

| 能力 | 可交付的成果 | 必要证据与工具 |
|---|---|---|
| 讲稿与分镜 | 来源可核的讲稿、镜头计划、字幕草稿、待执行步骤 | 文字/资料可读取；无媒体执行工具时明确尚未生成影片 |
| 图文讲解片 | 真实图纸/图片/文字的剪辑、字幕、可用且获授权的旁白/音乐 | 可读取素材、实际编码器；没有3D则不出现虚假旋转承诺 |
| 真实互动演示片 | 实际HTML中的方案、相机、图纸、指标或原册操作节选 | 指定源HTML可运行；浏览器、真实录制工具、操作与状态回执 |
| 空间语义/指标讲解片 | 功能热点、剖切、楼层或指标比较的讲解与演示 | 当前项目已经可验证的语义/统计能力；不能因能录屏而声称已核实建筑数据 |

能力分别判断。已具备的部分继续完成，被阻塞的指定部分保持 `blocked/degraded/not_run` 并说明影响。用户明确要求旁白、配乐或真实旋转时，缺该能力的替代稿不称为完整满足要求。

## 2. 先建立版本与覆盖表

在写长稿或录制前整理两张工作表：

1. `结论 → 源事实/页码/对象 → 必须/可选 → 讲解/操作/快速浏览 → 预计时间`。
2. `镜头ID → HTML hash → 章节/方案/功能/页码 → 实际操作 → 所需状态 → 相机/画幅 → 来源录制区间`。

覆盖状态至少区分“已展示”“快速浏览”“已讲解”“未提供/未验证”。每页露出一秒可以说明原册页序，不能称读者已经获得逐页详解。没有原册不生成假页；没有案例不凑案例；单方案不增加多方案比较。按当前资料定义 N 个方案、K 类功能、P 个原页，不能把 `3×5` 当通用矩阵。

记录录制快照与当前HTML的hash。当前HTML更新后，旧影片仍是旧快照的成果；不能改一个说明日期就称已重录新版。内容或操作变化时只重录受影响镜头；若用户要求反映最新界面，则更新相应来源、字幕、时间轴与验收记录。

## 3. 严格五分钟的时间预算

用户要求“不超过5分钟”时：**最终每份MP4的容器呈现时长必须 ≤300.000 秒，推荐剪辑目标295秒**。295秒是留给编码/尾帧及取整的余量，不是所有项目固定时长；用户另定上限时按其要求重新分配。以 `ffprobe` 的 `format.duration` 核查容器，同时检查视频/音频流起止，不能只根据讲稿字数、章节之和或视频帧数宣布满足上限。

按以下顺序控制预算：

1. 提取关键结论和必须保留内容，先写短稿。每段讲一个判断，数字、地名和方案名对照来源。关键概算/假设就近简洁交代，不在每句话重复通用免责声明。
2. 使用拟定声音生成小样，估算本语言实际语速。字数只作初估；原案例英文女声是可覆盖的声音预设，新项目可用中文、其他语种、男声、用户录音或无旁白方案。
3. 生成逐段旁白并读取实际音频时长/词边界，再冻结讲稿版本。不要先按理论语速锁死全部镜头。
4. 每段预留必要头尾时间，安排与其结论对应的真实操作。段长初步按 `max(旁白时长+头尾留白, 必须操作及阅读所需时间)` 计算，随后按输出fps转为整数帧。全片累计所有段、转场和片头片尾；转场重叠部分不能重复计时。
5. 时间轴每段、每镜头用连续整数帧分配，保存明确的起止。例：25fps下295秒为7375帧；换fps时重新计算，不能继承7375这个案例常量。
6. 超预算时优先删除重复表达、缩短片头/装饰停留、合并同类结论及可选镜头；重新配音、字幕与排镜。不要自动加速旁白、模型拖动或翻页来冒充正常阅读。若“全部条目详细讲解”和硬时限无法兼容，说明冲突并给出具体取舍，不能悄悄删必须项或宣称两者均完成。

下表可作为295秒概览片的初始分配，按项目取舍，**不是固定章节清单**：

| 阅读任务 | 初始秒数 | 调整原则 |
|---|---:|---|
| 开场、项目任务与结论 | 20 | 先让观众知道项目和比较目标 |
| 场地/空间问题与设计回应 | 45 | 室内项目可换为空间关系、场所与使用问题 |
| 方案、总图/平面、核心指标 | 80 | 核心设计或单方案也可占更大比重 |
| 剖面、功能与真实操作 | 65 | 根据实际模型与语义能力安排 |
| 案例或比较依据 | 40 | 无案例时用于设计重点，避免凑内容 |
| 原册/来源快速浏览 | 25 | 页数大时选重点或明确是快速浏览 |
| 收尾与下一步 | 20 | 只总结决策，不再次复述全部数字 |

## 4. 真实HTML互动录制

### 录制准备

- 从最终交付路径打开指定版本；核验hash，不能默认工程 `dist` 与正式HTML相同。原HTML保持只读，录制与派生文件进入独立工作目录。
- 选定语言与视觉主题，等待模型、图纸与字体加载。用当前页面真实DOM建立项目自己的操作映射，不复制原案例的全局对象名或选择器。
- 记录浏览器/录制工具版本、viewport、DPR、fps、主题、语言、方案和加载失败项。字幕/章节条所占高度在分镜中留出，避免盖住主图、热点和指标。
- 每段录制前建立明确初态，记录操作前后状态。只读状态探针可以取证；直接赋值或调用内部setter不能代替真实鼠标/键盘操作的验收证据。

### 动作与取证

以正常可见控件、鼠标拖动、滚轮、键盘或页面真实公开交互入口进行演示。使用短镜头录制一次操作及稳定停留，减少长录屏的内存与磁盘压力。CDP、系统录屏等都可使用，以实际可用工具为准。

旋转镜头至少保存：源clip与hash、动作类型/目标、动作起止、对应方案、相机/原生旋转状态，以及实际帧变化。镜头的 `sourceStart + motionDuration` 必须落在源视频范围，且处于真正拖动或自动旋转时段。模型重置之后的静止画面不能因为clip曾旋转过就标为旋转。

图像像素差只能辅助确认有变化：字幕、光照、鼠标、方案换图也会变化，不能单凭像素差宣称几何旋转。阴影关闭/开启按阴影操作描述，不能称为日照验证；剖面着色按真实样式变化描述，不能称新生成真实剖切。

原速剪辑真实动作，必要时在动作完成后延长其真实最后一帧以配合旁白。静帧必须来自相应正确状态，不自行重绘模型冒充录制。若采用受控帧时间离线录制，仍必须调用原页面真实renderer并验证相机/动画推进；未验证的RAF替换不能称为确定性录制成功。

## 5. 多风格、字幕和双比例画面

沿用 [六种视觉风格](styles.md)。主题可影响片头、背景、章节条、字幕面板与封面；功能色、方案ID、建筑几何、指标和原册内容不随风格变化。默认选择一个连贯风格；仅在用户要求时增加其他风格版本或样片，不强制把六种都塞进同一影片。

旁白、字幕和当前画面讲同一方案/结论。优先使用配音词边界或实际字幕时间，段首留白计入全局偏移。字幕有断句、可读字号、足够对比度和安全边距；避免遮挡图纸说明。烧入字幕与外置UTF-8 SRT可同时交付，外置字幕仍须与每份对应影片匹配。需要双语时按语言分别排版并核查长文本，不强制所有项目双语。

可配置输出预设：横版1920×1080/16:9，竖版1080×1920/9:16，25fps；用户目标不同则调整。只制作所请求的比例/渠道。横版可保留完整主图，竖版按章节重新取景：放大当前主图/模型并保留完整上下文小窗，或使用适合内容的竖版版式。不能将整幅横版横向拉伸，也不能盲裁掉建筑、图例、数值或翻册正文。图纸小窗承担上下文，不承诺其小字在手机上都可读；重要读数另给特写或字幕。

MP4/H.264、yuv420p、方形像素SAR1:1、AAC是当前视频schema的兼容输出预设；分辨率、fps、比例和体积按用户设备/目标配置。若另需其他编码/像素格式，先扩展相应配置契约与实际导出/验证实现，不能提交schema不接受的值并称已支持。导出后核查实际SAR/DAR，不能仅依据像素宽高判断比例。在线播放文件可做faststart；章节、封面和外置字幕一并检查。

制作“小红书版本”“微信版本”表示准备了适配下载文件。视频号、朋友圈、微信聊天文件是不同入口；不能混用上传限制。平台约束会变化，用户要求渠道适配时优先核查当前官方页面并保存日期与来源，无法确认的上限保持未知；前端代码分支、历史报道不等于用户账号当前权限。未实际上传不得称平台验证通过，制作文件不授权对外发布。

## 6. 旁白、音乐许可与混音

旁白可来自用户授权录音或当前可用TTS。记录语言、声音ID/提供者、速度、讲稿hash、服务版本及相应使用条款；不能因接口免费或暂时能调用就承诺所有公开/商业用途已获许可。使用在线或付费服务仍遵守会话授权与数据范围；没有服务能力时保留讲稿/字幕计划，或使用用户已允许的替代。

配乐可使用用户提供且许可适用的音乐，或原创合成。记录作者/来源、许可范围、署名要求、音轨hash。原创合成记录生成脚本、种子、算法/音色来源、是否使用第三方样本及最终长度；不以“原创”字样掩盖下载音乐或未授权采样。舒缓器乐是建筑汇报的可选方向，不固定64BPM、电钢或某个和声；采用分块生成避免整片浮点音频占满内存。

声音小样检查地名、数字、缩写和停顿。旁白作为主要可理解内容，配乐在人声段压低；侧链压缩或音量包络均可，不能只拼接两条同响度音轨。剪辑到实际片尾后重新施加配乐渐出，不能依赖较长音乐文件的原有片尾渐出。

量测独立音轨与最终混音的时长、峰值/RMS、综合响度、真峰值、削波；在有人声/无人声片段核查配乐与人声的相对电平。综合响度合格不能单独证明人声清楚或声音自然，应在工具可用时试听开头、关键读数、转场与片尾，记录实测/试听范围。参考案例的音乐约−23LUFS、混音约−17LUFS是案例结果，不是平台统一要求。没有实际试听不称已完整听审。

## 7. 工具、缓存与能力降级

[video_tools.py](../scripts/video_tools.py) 的 `plan` 与 `verify` 是辅助规划和检查入口；调用前查看该版本帮助与 [视频schema](../assets/video-manifest.schema.json)。它们不能替代浏览器录制、TTS、编曲、完整剪辑合成或平台上传，不得因规划成功就称影片已生成。`plan` 无需打开HTML；`verify` 的可选HTML来源检查不能代替许可、事实、真实互动与试听审查。只声明该版本实际执行的检查，输入schema与CLI参数以随技能包提供的版本为准。

复制 `assets/video-intake.json` 到项目目录作为 `video-project.json`，保持技能原模板不变。启用请求、填来源与偏好后，由当前项目提取场景；配音实际生成后，逐段填写相对于配置文件的音轨路径。例如加入一个场景：

```json
{
  "id": "design-intent",
  "title": "设计目标与空间回应",
  "chapter_id": "当前HTML的实际章节ID",
  "source_refs": ["资料页码或对象定位"],
  "claim_status": "sourced",
  "narration_text": "已经对照资料核对的讲稿",
  "narration_audio": "audio/design-intent.wav",
  "lead_seconds": 0.35,
  "tail_seconds": 0.85,
  "min_visual_seconds": 8,
  "actions": []
}
```

这是填入 `scenes` 的一段结构，路径与文字必须换成当前项目的实际值；不是已经存在的音轨或自动配音命令。发现阶段模板 `scenes: []` 是待提取，排时命令会拒绝空场景。无旁白时 `voice.enabled=false`，可用实测静音音轨辅助技术排时，不能把它称为已经配音。

在技能目录下调用，用当前环境真实路径替换项目及工具路径：

```sh
python scripts/video_tools.py --help
python scripts/video_tools.py plan --config /project/video-project.json --ffprobe /tools/ffprobe --output /project/timeline.json
python scripts/video_tools.py verify --video /project/landscape.mp4 --ffprobe /tools/ffprobe --ffmpeg /tools/ffmpeg --max-seconds 300 --aspect 16:9 --report /project/qa-landscape.json
python scripts/video_tools.py verify --video /project/portrait.mp4 --ffprobe /tools/ffprobe --ffmpeg /tools/ffmpeg --max-seconds 300 --aspect 9:16 --subtitles /project/narration.srt --report /project/qa-portrait.json
```

HTML来源可额外传 `--source-html /project/final.html --expected-source-sha256 <录制时源hash>`。这检查文件与所给hash是否一致，不能单独证明视频来自该文件，须结合录制回执和画面证据。`plan` 仅验证测时输入与预算；运行前另按 schema 校验项目配置、确认来源/声音/素材使用依据，运行后也不自动将 `validation.state` 改成整流程通过。Windows 可使用带引号的绝对路径，工具未安装时报告真正缺项。

需要完整执行时，按环境组合最小流程：旁白/字幕生成、浏览器录制、时间轴/混音/合成、最终验证。运行库、浏览器、编码器路径由当前环境发现或配置；不能要求下一位GPT拥有原作者的C/E盘路径。先核查实际FFmpeg/ffprobe、字幕渲染与音频过滤器能力，再选择实现，不仅检查程序文件存在。

缓存签名应覆盖相关输入文件hash、讲稿/声音参数、动作或裁剪计划、主题/字幕/字体、viewport/fps、适配器与编码参数版本。不能只检查目标文件存在或帧数相同。修改某段讲稿、动作或来源时只失效受影响缓存，同时重建其后的字幕偏移和总时间轴。

| 缺少能力 | 可以继续做 | 必须明确的未完成项 |
|---|---|---|
| 只有普通GPT文本能力 | 来源整理、短稿、分镜、输入配置、待执行代码 | 未写文件/未配音/未录制/未导出/未验证，不伪造下载链接 |
| 可编码但无浏览器或模型解析 | 据真实图纸/用户录制素材制作图文片 | 没有当前HTML真实交互录制；素材版本无法核实时保留unknown |
| 浏览器运行但WebGL失败 | 可用的图文/原册操作录制，保留失败回执 | 没有可见模型旋转，不能用静态图片证明3D成功 |
| 无TTS、无音乐许可或合成依赖 | 继续短稿、字幕与无依赖镜头；使用已获许可且实际可用的素材 | 用户要求的旁白/配乐若未满足，交付仍是部分成果 |
| 无字幕渲染/最终QA工具 | 保留外置SRT、母素材及待执行命令 | 烧入字幕或最终验证标记not_run；不能称全流解码/同步通过 |
| 无平台账号/上传权限 | 制作本地下载版、封面、ZIP与使用说明 | 没有实际上传，不称平台接受或已公开发布 |

## 8. 成片验收与交付

按 [视频验收清单](acceptance.md#8-可选视频验收) 对母版及每个派生比例分别检查，记录最终路径/hash、所用HTML快照hash、时间轴hash、工具版本、成功/失败/未测项：

- 容器时长在用户硬上限内；视频/音频起止、帧数、整数帧时间轴、字幕/章节与实际画面对应。AAC末帧可能产生少量解码补齐，须量化其样本数与呈现时长；不能用编码补齐解释大幅漂移，也不能放宽300秒容器上限。
- 实际分辨率、fps、编码、像素格式、SAR/DAR、声道/采样率、文件体积符合输出目标；对全部音视频流进行完整解码，不能只抽帧或只验证开头。
- 抽查每章与重要操作区间，核对方案、功能、页码、真实动作及字幕读数。原模型旋转有原生状态与画面证据，静帧与阴影切换按实际作用记录。
- 混音无削波，旁白清楚，片尾完整，配乐不盖住关键读数；字幕、图纸、封面在目标手机/桌面尺寸可读，不因竖屏重排裁掉重要来源内容。
- 导出和验证前后文件hash相同，缓存与来源一致；ZIP能够解压并核验内部文件CRC/hash。验证失败先修复或说明边界，不用旧报告覆盖新文件。

交付包含用户请求的MP4版本、外置字幕、封面/打包文件、简短使用说明、来源与音频许可说明、验证摘要；时间轴、操作回执和可维护脚本按维护需要提供。保留原HTML与原资料，概览片说明浓缩范围和快速浏览范围，详细阅读仍可回到原HTML/原册。实际播放/试听范围与技术解码范围分别表述，最终回答给可下载路径和真实验收状态。
