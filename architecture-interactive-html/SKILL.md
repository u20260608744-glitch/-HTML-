# 建筑交互 HTML 方案册

将不同项目的资料组织为可阅读、可比较、可操作的建筑交互页面。以已完成的 Woodlands HTML 为成果参照，复用其阅读秩序、图文对齐、主体居中和真实交互，不继承该项目的名字、地域、数值、三方案、17 页、材料分类或固定章节数。

适用住宅、办公、商业、公共建筑、园区、更新、室内与景观项目。项目可只有一个方案，也可有多个方案。用户的明确要求优先于本技能的默认选择。创建 HTML 与深化/修改建筑设计是两个不同任务；仅要求页面时，不擅自改建筑几何。

## 先读什么

- 每次开始：[输入条件与能力分级](references/input-requirements.md)。
- 需要向用户收集资料：使用 [用户填写表](references/user-intake.md)，先从已有附件提取，保留真正缺失的提问。
- 准备生成：阅读 [数据与实现契约](references/build-contract.md)。
- 决定视觉系统：阅读 [六种风格与选择方法](references/styles.md)，可展示 `assets/style-gallery.html`。
- 准备交付：阅读 [验收与交付](references/acceptance.md)。
- 用户问“这份成果具体依赖什么”：再读 [Woodlands 成果审计](references/woodlands-audit.md)。此审计只解释原案例，不作为新项目的输入数据。

`assets/project-intake.json` 是可填写的结构化输入；`assets/project-manifest.schema.json` 描述其结构。普通用户可以只填写 Markdown 表并附文件，由模型生成 JSON，不要求用户懂代码。

## 1. 先建立输入清单和能力表

先检查当前目录、用户附件、现有 HTML/源代码和指定资料；不要先重建工程。列出文件名、类型、版本、用途、来源及读取结果。对将进入最终成果的关键源文件记录 SHA256；原文件保持只读，转换、裁图、模型导出进入工作副本。

从资料中提取：项目名称/地点/阶段、方案 ID、图纸页码、单位和轴向、约束、指标、空间说明、原生相机、素材署名。不得把用户已提交的信息重新整表询问。

首次回复给出三个具体结果：

1. **已具备**：找到哪些文件、能直接实现哪些模块。
2. **需补充**：仅列影响指定功能的缺失项，说明对应影响。
3. **可先做**：不依赖缺项的部分及资料不足时的真实替代。

将缺项分为：阻塞指定能力、可继续但须保留 unknown、只影响表现的可选项。一般把相关问题合并为 1–3 个易回答的问题；资料分多批时逐步补齐，不一次要求用户填完全部技术字段。

构建需整理项目识别信息、用途/读者、阶段、内容资料、要求的功能、语言、视觉方向和交付方式，但不等于用户必须手填全部字段。普通图文页的最低条件是至少一份可读取资料或明确项目叙述，以及可确定的展示目标；工作名、通用展示、语言、风格和本地交付可采用已说明的合理默认值。已有文件能回答的字段直接提取，缺阶段可保持未知并继续。只有阻塞用户指定能力的缺项才要求补充；单位、真北、指标口径、功能语义不能用视觉默认值代替。

## 2. 按真实输入选择生成级别

| 级别 | 可交付 | 关键条件 |
|---|---|---|
| 图文交互 | 章节导航、图纸缩放、场地阅读、指标表、原册阅读、双语 | 可读取的图纸/图片/文字；指标有来源才显示数字 |
| 原模型交互 | 上述内容 + 真正旋转/平移/缩放、方案切换、材质/阴影 | 可解析原生模型或可信导出；方案与主体范围已识别 |
| 空间语义交互 | 上述内容 + 功能着色/热点、真实剖切、构件或楼层筛选 | 模型语义映射、楼层/剖切条件等明确且可验证 |
| 可核指标/地理分析 | 对应面积计算、比例尺、真北、周边高度与覆盖分析 | 各能力分别具有可信尺度/坐标/语义/口径，不因有模型而自动成立 |

各能力独立判断。有 3D 不代表能计算法定容积率；有 PDF 不代表能复建真实模型；有体量不代表有 BIM 构件。缺少原模型时，可先交付真实的图纸交互版；“拖动旋转”入口仅在确有模型时出现。用户另行授权概念建模时，明确作为概念补模，不称为原模型。

如果指定能力不可实现，指出所需文件格式或缺失语义，并继续完成已具备的部分。未知项使用 null 或“待核实”，不填 0，不造比例尺、停车数、地形、建筑层高、周边建筑或分析结论。

## 3. 规划资料驱动的章节

先生成一份短的“章节—结论—主图—说明—操作—来源”映射，随后实现。一般阅读顺序为：

`项目与任务 → 场地 → 设计回应 → 形体/方案 → 总图与指标 → 剖面 → 功能与日常空间 → 参考案例 → 比较 → 原册/来源`

这只是默认顺序。室内项目可用“空间关系/平面”代替场地与总图；单方案删除多方案比较；没有原册则使用已提供的图纸画廊，不生成假的册页；没有案例不凑案例。不要删除用户已有且要求保留的章节。原有总图应放在形体讲解与剖面之间，除非用户另定叙事。

同一方案的 ID 在所有章节保持一致。方案名可以翻译，ID 不能因名称或排序变化而错配。方案数量 N 和原册页数 P 从资料读出。多于三方案时选择可阅读的网格或原生切换，不将所有卡片硬塞成极窄列。

同一阅读任务的内容同时呈现：设计愿景与具体回应、功能模型与功能解释、总图与经济指标。方案、场地分析种类、材质、阅读模式等真正不同状态才使用切换。

## 4. 选择风格，保持功能一致

提供六种完整方向：**深林编辑、白纸作品集、蓝图技术、砂岩展馆、瑞士网格、单色展廊**。见 [风格规范](references/styles.md) 和 `assets/theme-presets.json`。

用户可以选择一种作为最终风格，或明确要求在成品里保留风格切换。默认交付一种连贯风格，并提供风格预览；不自动给正式页面增加六个风格按钮。多种风格改变配色、字体搭配、图文组织、背景质感和动效，不改变来源、指标、功能分类、相机语义和交互行为。

功能分区颜色与装饰强调色分开。整份页面中的同一功能使用同一颜色/编号/文字，切换视觉主题后仍可识别；不要仅凭颜色传达信息。

## 5. 实现必须保留的构图与交互

- **主体居中**：建筑自身投影范围的中心与图幅中心对齐。主体选择依据源对象层级/语义/用户确认，排除周边道路、地面、树和车辆。只改相机取景，不改世界坐标来凑画面。
- **等比排版**：同一比较组的图框上下对齐、同高；文字共用行轨道。图片等比填充。源图完整阅读使用 contain；展示性缩略图可 cover，裁周边留白，不裁掉需要阅读的图例、尺度、建筑主体。
- **场地同构图**：各分析共用一致高度，右侧地图在分析切换时不跳高；左图与右侧说明整体上下对齐。场地边界采用红色虚线、清晰红色 SITE/BASE 标注；名称放在标题或侧栏，不遮挡纯图。
- **总图可核**：图与右侧指标齐高；指北针置于图框右侧。比例尺长度由配准与视域计算，不能装饰性随意缩窄。总图显示用地面积、FAR、密度、基底/占地口径，再列分项与停车，缺值显示待核或省略不适用项。
- **模型状态**：回到首个轴测预设恢复自动旋转；尊重用户手动暂停和系统减少动态偏好。功能模型旋转可另设为用户开启，初始阅读稳定。
- **操作单一**：同一区域中打开同一模型/同一原册的重复按钮合并为一个。章节导航与有明确方案/页码上下文的入口可共存，不能为了去重而删掉必要导航。
- **草图与光照**：草图风格可用细方格纸、墨线、马克笔或淡彩；其余风格按主题选择背景。主光照向相机可见面，阴影不遮没主体；没有地点/时刻/朝向与真实太阳计算时，仅称观看光照。
- **实体与绿化**：保留源层级和来源。配置或替代配景仅在已授权且有点位/规则时进行，避免室内、建筑体量、洞口和边界；不要把配景误读为建筑几何。
- **原册**：原页顺序、比例、正文完整；支持相应页数、目录、翻页/按键/触摸、单页/双页、缩放。移除无用白色叠层条，不通过裁内容掩盖问题。
- **语言与设备**：切换语言后名称、描述、单位、热点、图注、按钮和状态一致。桌面以一章节一屏为默认；手机复合图文可自然滚动，文字不能靠无限缩小、遮挡或隐藏实现一屏。

具体算法、状态接口和依赖处理见 [实现契约](references/build-contract.md)。

## 6. 保持来源边界

资料中每个关键事实保存 source、页码/对象/表格行、status、单位及口径。区分原文事实、独立计算、明确假设与设计回应。案例相似性、卫星目测和着色片区面积不能冒充测绘或性能验证。

面积：明确用地、基底、建筑面积、计容面积、地上/地下及总建模面积的区别。停车面积换算必须给假设、范围和“概算”状态。图框/楼层文字只约束所属图框；缺失层高、屋顶标高和真北不从其他图框继承。

网页引用的案例、法规、天气与公共事实需要时，按当前环境可用工具核实并留来源。只使用授权素材，记录第三方照片署名。离线展示可保留可点击出处；运行自身不能依赖访问外网。

## 7. 交付前验证，避免只给代码

对最终构建文件执行 [验收规范](references/acceptance.md)：内容/来源、真正交互、视口几何、不同语言、不同方案、离线请求、移动触摸/键盘和能力降级。测试覆盖真实状态，不能用 mock 成功代替打开模型或渲染。

至少核验桌面较宽/较窄和手机尺寸；已有针对性测试通过后，不因追求检查数量反复跑无关矩阵。缺工具时记录实际未验项，不能称完整通过。

交付默认包含最终 HTML、输入清单与缺项、来源/指标表、验证摘要；复杂项目保留可维护源代码与 build receipt。单文件离线时嵌入必须的运行时、模型、图片与有许可字体；若体积或模型解码限制使多文件本地站点更合适，先清楚说明交付差异。上传/公开发布/付费 API 不因本技能自动获得授权。

旧成果需要更新时先备份，校验成品与已测试版本一致，再打开交付页面。最终回答简短说明路径、可用能力、验证结果和真实未完成项。

## 无代码执行工具的 GPT 环境

本技能也可作为附件或系统提示给普通 GPT 使用。仍先输出已提取条件、缺项、模块计划和选定风格，再提供完整可保存的 HTML/源文件。不能实际读取的附件、不能导出的原生模型、不能运行的交互均说明边界；只输出 HTML 文本时称“已生成代码，尚未运行验证”。不要声称已写文件、已打开页面、已安装技能或已验证离线。
